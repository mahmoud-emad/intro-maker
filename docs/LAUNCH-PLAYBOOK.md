# Launch playbook (internal, not linked from README)

No tactic guarantees stars. What reliably helps is a great demo, a 30-second install, and showing up where the audience already is.

## Before launch (do all of these)

- [ ] Replace every `YOUR_USER` / `YOUR_NAME` placeholder
- [ ] Run `/intro` on this repo itself; commit the result as `docs/assets/demo.mp4` + `demo.gif` (self-demo = the brag.md trick)
- [ ] Render one example per style (6 total) and link GIFs in README
- [ ] Verify clean-machine install from the README, line by line
- [ ] Repo description: "Generate a YouTube intro from one Claude Code command"
- [ ] Topics: `claude-code`, `youtube`, `intro-maker`, `video-generation`, `hyperframes`, `agent-skills`, `motion-graphics`, `ai-video`
- [ ] Social preview image (1280x640): the demo frame + `/intro`
- [ ] Enable GitHub Pages from `/docs`; enable Discussions
- [ ] 5 `good first issue` items (new style, new audio, vertical polish...)
- [ ] Tag `v0.1.0` release with the demo MP4 attached

## Launch week

- Show HN: "Show HN: /intro – generate a YouTube intro from one Claude Code command" (lead with the video, be around to reply)
- r/ClaudeAI, r/ClaudeCode, r/youtubers, r/SideProject (follow each sub's self-promo rules)
- X/Twitter + LinkedIn: post the demo MP4 natively, not just a link
- Product Hunt (separate day)
- Submit to awesome lists (awesome-claude-code and similar), skills directories, and the `skills` CLI index
- Make your own channel's intro with it and say so

## After

- Reply to every issue/PR in < 24h for the first month
- Ship a small release weekly (new style, new format) and post each one
- Ask users to post their intros and tag the repo; feature the best in `examples/`
- Consider a hosted no-install version later (brag did this)

## Don'ts

- No buying stars, star-for-star swaps, or bot engagement: GitHub removes them and it kills trust
- No spamming communities
